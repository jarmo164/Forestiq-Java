# Role-Based Usability Baseline Plan

Status: ready for sessions

## Privacy and Consent

ForestIQ usability sessions must collect only work-task evidence needed to prioritize product decisions. Do not record personal identity codes, owner names, phone numbers, emails or real deal notes in the research log. Use participant labels such as `P1-caller`.

Before starting, tell each participant:

- the session evaluates the product workflow, not the person;
- participation is voluntary and can stop at any time;
- notes are anonymized;
- task timings, success/failure, hesitation and comments are recorded;
- production customer/personal data should not be copied into research notes.

## Task Scenarios

| Scenario | Caller | Evaluator | Sales manager | Administrator |
| --- | --- | --- | --- | --- |
| Start workday | Open dashboard, identify next owner to call | Open evaluation queue | Review team workload | Review system/service status |
| Find owner and follow-up | Search owner, inspect history, add outcome and reminder | Inspect owner context and parcel facts | Reassign owner or case | Confirm role/access visibility |
| Map to qualification | Select parcel on map, open detail, decide call relevance | Inspect parcel/forest facts and evidence | Check portfolio opportunity | Validate source freshness/errors |
| Evaluation decision/conflict | Escalate unclear status | Decide evaluation or conflict resolution | Approve/prioritize exception | Inspect audit trail |
| Role or mass assignment | Not primary, observe impact | Not primary, observe impact | Bulk assign/rebalance | Change role or mass assignment safely |

## Metrics

For every task capture:

| Metric | Scale |
| --- | --- |
| Success | Success / partial / fail |
| Time | Seconds from task start to outcome |
| Help needed | None / hint / step-by-step |
| Errors | Count and description |
| Confidence | 1-5 |
| Severity | Low / medium / high / blocking |
| Backlog link | Existing issue or new issue |
